# CLIN-7 진료 프로토콜 나무 (Clinical Protocol Tree)

> **한 줄 정의**: 증상 → 문진 → 검사 → 감별 → 치료 → 티칭 → 결과 → 내 숙련도로 이어지는 가지치기 프로토콜을 **볼트 md로 쌓고**, 진료 중에 AI가 **지금 걸어온 경로**를 함께 보는 임상 도구.

## 2. 6층 구조

| 층 | 이름 | 노드 예 | 필수 필드 |
| :--- | :--- | :--- | :--- |
| **L0** | 증상 진입(Entry) | 두통 · 어지럼 · 어깨 통증 · 손저림 · 복통 · 소화불량 · 피로 · 부종 · 불면 | 주호소 정의, 이 증상의 레드플래그 목록 |
| **L1** | 분기 문진(Ask) | "밤에 깨서 두통 때문에 잠에서 깨나요?" | **왜 묻는가 1줄** + yes/no 다음 노드 |
| **L2** | 검사(Test) | 경추 압박검사(Spurling), 초음파, CRP, 소변 | 민감도·특이도·LR+, **이 검사로 무엇을 배제하는가** |
| **L3** | 감별(Dx) | 긴장성 두통 / 경추성 두통 / 편두통 / 거미막하출혈 배제 | 후보 3~5 + 확률을 올리고 내리는 소견 + **질환 노트 링크** |
| **L4** | 치료·티칭(Treat/Teach) | 침·약침·한약·추나·부항 세트 + 자침점·용량·빈도 | 재평가 시점(3일/1주/4주), 전원 기준, **환자 설명 3문장** |
| **L5** | 결과(Outcome) | NRS 전/후, 부작용, 순응도 | 다음 개정의 근거 |
| **S** | 스킬 레지스트리 | "경추부 심자", "견갑상 신경 약침" | 숙련도 0~5, 시행 횟수, 금기, 감독 확인 |

- **레드플래그는 L1 첫 노드**로 고정한다. 어떤 경로로 들어와도 스크리닝을 통과하지 않으면 L2로 내려가지 않는다.

## 5. 프로그램 4단계

| 단계 | 내용 | 기간 | 완료 기준 |
| :--- | :--- | :--- | :--- |
| **P0 노트 검증** | 두통 1개 증상만 손으로 완성(노드 30개). 앱 없음 | 1~2주 | 실제 진료에서 종이 대신 이 노트를 폈다 |
| **P1 읽기 전용 진료 뷰** | `tree.json` 생성 → 단일 HTML/로컬 서버. 증상 선택 → 트리 → 노드 카드(문진 체크리스트·치료 세트·교육 스크립트) | 2주 | 증상 선택 → 치료 카드까지 **3클릭·10초** |
| **P2 기록·통계** | 케이스 결과 입력 → 노드별 반응률·전원율 → 개정 후보 자동 제안 | 3~4주 | 표본 5건 이상 노드에서만 개정 후보가 뜬다 |
| **P3 스킬·회고** | 숙련도 대시보드 + 주간 회고 크론 | 이후 | 주 1회 "이번 주 새로 익힌 술기 / 막힌 노드" 1줄 |

- Obsidian은 **작성**, 앱은 **진료용**. 둘은 같은 md를 읽는다(복제 저장 없음).
- 진료 뷰는 LLM 없이도 100% 동작해야 한다(네트워크·모델 지연이 진료를 막으면 안 됨).

## 6. AI 도움 3단계 (진료 중)

1. **결정론(기본)** — 앱이 트리·체크리스트·교육 스크립트를 그대로 표시. 지연 0, 근거 고정.
2. **LLM 점검(선택)** — 지금 걸어온 노드들만 컨텍스트로 주입해 3줄만 답한다: ① 아직 안 물어본 것 ② 감별 누락 ③ 금기 위험. **노드 근거 밖 발언 금지, 모르면 "프로토콜에 없음"**.
3. **사후 개정** — 케이스 로그 → "이 경로는 트리에 없었다" → 개정 후보 큐 → 비오님 승인 → `90_개정이력`에 사유·근거 기록.

- RAG(벡터 검색) 아님 — KNOW-1 원칙대로 **허브·index·선택 노드만 따라가는 traversal**.

### 안티그래비티에 시키는 방식 (실패 방지 4조)

1. **탐색 금지** — 입력 파일 경로·출력 경로·노드 ID 목록을 프롬프트에 전부 적는다. (`AGENTS.md` 38KB 로딩으로 20분 타임아웃·산출 0 전례)
2. **1배치 20~25노드**, `--print-timeout 30m`, 모델은 Flash(High)로 충분. 판독·설계만 Pro.
3. **PMID는 조회 확인값만** 적고, 미확인은 `PMID 미확인`. 추정 금지.
4. 산출 후 `python build_tree.py --check`를 통과해야 "완료"로 인정.


## 10. 안전·거버넌스

- 프로토콜은 **참고 도구**이고 최종 판단은 의사. 모든 트리 상단에 이 문구를 고정한다.
- 레드플래그·전원 기준은 **생략 불가 필드**(스키마 검사에서 실패 처리).
- 환자 식별정보는 볼트에 넣지 않는다(LLM_Wiki_SCHEMA §2). 케이스는 비식별 요약만.
- 근거 없는 치료 세트는 `신뢰도: 하` + `(경험 기반)` 표기 — 경험과 근거를 섞어 쓰지 않는다.
- 개정은 되돌리지 않고 `90_개정이력`에 사유를 남긴다.
